HSK Contract Watchdog

An agent watches verified HashKey contracts, flags obvious issues, and does not publish the bug. It leaves a public caution in a registry on HSK. Only the contract owner() can unlock the writeup.

No draining. No bounty. No X/Telegram dump of the exploit.

Out of scope

Stealing / rescue-drains · paid bounties · DMing guessed handles with bug details · painting a banner onto Blockscout · full audits · extra vuln-class theater.

How it works

1

Watch

Agent polls HSK Blockscout for newly verified contracts. For each one it notes deployer, owner(), proxy implementation, and obvious bytecode clones of known tokens.

2

Check

A few automatic, checkable rules on source — missing access control, tx.origin, unlocked selfdestruct. Not a real audit. Flag or skip.

3

Seal locally

If flagged: write the report (address, issue, snippet) on the agent server. Compute keccak256(report). Bug text never goes on-chain.

4

File on HSK

Agent wallet sends a tx to the Registry on HashKey (testnet 133): contractAddress, reportHash, severity, state = SEALED. Event SealedReport(contract, owner, reportHash). The explorer shows a sealed report was filed — no bug text in the tx.

5

Public warning — the public good

The warning isn't on their bytecode or a Blockscout sticker. It's reports[0xABC] in the registry. Any UI, agent or dapp calls hasSealedReport(0xABC) and can refuse to touch it. Users are protected even if the owner never reads the writeup.

6

Optional nudge

A 0 HSK tx to the owner EOA (never into the bad contract), or a ping: “this address has a sealed report, open the page.” Still no bug text.

7

Owner unlocks (pull)

Owner opens the site, connects the wallet that is owner() / proxy admin / Safe, signs. Server checks HSK. Match → the report renders on that page. Wrong wallet → nothing. Wallets have no inbox; this page is the delivery.

8

Ack

Owner can ack(reportId) from that wallet: SEALED → ACKED. The flag stays until they ack. The exploit is never published.

Why it matters

Disclosure today is a DM into the void or a public dump. This makes the warning machine-readable and on-chain, and the writeup private to the only wallet that can fix it.
